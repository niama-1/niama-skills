## 作用范围限制

只允许依赖以下材料完成任务：
1. 当前任务目录中的文件
2. 用户在当前任务明确提供的文件
3. 用户当前明确授权或已经提供的目标页面材料
4. 当前目录 `ruyitrace/index.jsonl` 和根目录 `*.http_packet.json` 中与目标直接相关的捕获请求与响应
5. 当前目录中与目标直接相关且匹配目标的 `ruyitrace/`
6. 当前目录中与目标直接相关的旧版离线抓包归档（仅兼容，不作为默认输入）
7. 当前 skill 自带的 `assets/rtproxy.js` 源文件

严格禁止：
- 去无关历史项目目录找旧环境
- 用未经用户授权的历史 `env.js`、旧 `test.py`、旧日志补齐当前任务
- 材料不足时自行切换到其他目录寻找“相似实现”
- 把 `补环境结构图.js` 里的站点业务代码、示例参数、`debugger`、全量枚举表或无关对象直接搬进当前目标项目
- 除非用户在当前任务中明确要求，否则不得使用 Playwright、Puppeteer、Selenium、Camoufox 或同类浏览器/页面自动化程序进行自动点击、登录、翻页、滑动、输入、拖拽或触发业务动作
- 用浏览器/页面自动化程序跑出的参数、状态、事件轨迹或页面结果替代本地 `code.js` / `runtime/*.code.js` 实现
- 材料不足时自行用自动化程序接管页面、执行业务动作或补齐缺失证据
- 因为 trace 中存在或本地缺口日志出现，就补入与当前目标集合无关的浏览器对象、指纹面、DOM 内容、事件状态、接口或其它参数族

如果材料不足，只能：
- 让用户补充目标 URL、触发步骤、抓包或 trace
- 分析当前任务目录已有的 `ruyitrace/`、`jscall`、目标 JS、日志和包证据
- 使用 `ruyitrace/index.jsonl` 和根目录 `*.http_packet.json` 确认请求链
- 明确记录缺失项，不猜关键环境值，不自行启用浏览器/页面自动化

补环境作用范围必须按“目标集合相关、链路内语义完整”执行：
- 目标集合可以是一个或多个参数、token、签名片段、加密请求片段、验证码凭证、Worker 返回值或业务动作状态
- 只补与目标集合的生成、校验、注入、请求组装或最终验证直接相关的对象、字段、方法、事件、Worker 消息和状态
- 目标集合外不扩张；目标链路内不补空壳
- 待确认环境项不得直接写入交付版 `code.js`，只能记录为候选缺口并等待证据确认
